# 🛡️ أمن واجهات الـ API — كود هشّ مقابل كود آمن

مشروع تعليمي في **الأمن السيبراني** يشرح ثلاثًا من أشهر ثغرات واجهات برمجة التطبيقات (API)
حسب تصنيف [OWASP API Security Top 10](https://owasp.org/API-Security/)، بمقارنة مباشرة بين
الكود الخاطئ والكود الصحيح — بأمثلة عملية بلغة **C#** على **ASP.NET Core 8**.

🔗 **العرض المباشر:** بعد تفعيل GitHub Pages سيظهر الرابط هنا.

## الفكرة

لكل ثغرة نعرض: الخطر → الكود الهشّ → مثال الاستغلال → الكود الآمن → الدرس المستفاد.

| # | الثغرة | التصنيف | الإصلاح الجوهري |
|---|--------|---------|------------------|
| 1 | حقن SQL | API8 — Injection | استعلامات مُعامَلة + التحقق من المدخلات |
| 2 | مصادقة مكسورة | API2 — Broken Authentication | bcrypt + JWT + تحديد المعدل |
| 3 | كسر التحكم بالوصول (IDOR) | API1 — BOLA | التحقق من ملكية المورد على الخادم |

## المحتوى

- **`index.html`** — موقع تعليمي عربي تفاعلي (يعمل بالمتصفح مباشرة، بلا أي بناء).
- **`assets/`** — التنسيقات (CSS) ومنطق الصفحة (JavaScript).
- **`api/`** — مشروعان حقيقيان بـ ASP.NET Core 8: نسخة هشّة ونسخة آمنة، لتجربة الفرق عمليًا.

## التشغيل محليًا

الموقع: افتح `index.html` بالمتصفح مباشرة.

أمثلة الـ API (تحتاج [.NET SDK 8](https://dotnet.microsoft.com/download)):
```bash
dotnet run --project api/Insecure   # النسخة الهشّة (منفذ 5000) — للتعلّم فقط
dotnet run --project api/Secure     # النسخة الآمنة (منفذ 5001)
```
التفاصيل وأمثلة المقارنة في [`api/README.md`](api/README.md).

## النشر على GitHub Pages

من صفحة المستودع على GitHub: **Settings → Pages → Source: Deploy from a branch → Branch: `main` / `root`**،
ثم انتظر دقيقة وسيظهر الرابط العام.

## ⚠️ تنويه أخلاقي

النماذج الهشّة لغرض التعليم فقط. شغّلها محليًا لفهم الخطأ وإصلاحه، ولا تنشرها في بيئة حقيقية،
ولا تختبر هذه الهجمات على أي نظام لا تملكه أو ليس لديك إذن صريح به.
